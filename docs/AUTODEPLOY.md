# Автодеплой Recall на VPS

GitHub Actions запускает **Deploy Recall** при пуше в `main`. Workflow подключается
к VPS по SSH, обновляет рабочую копию до актуального `origin/main`, собирает образ
из существующего Dockerfile и ждёт успешного healthcheck контейнера. Деплои
выполняются по одному. Если сборка образа завершится ошибкой, замена контейнера
не начнётся. Если контейнер заменён и не прошёл healthcheck, workflow завершится
ошибкой. Автоматический откат при этом не предусмотрен.

## Один раз на VPS

1. Подготовь Linux с Git, Bash, `flock` и Docker Compose с поддержкой `up --wait`.
   У пользователя для деплоя должен быть доступ к Docker и право записи в папку
   проекта. SSH должен быть доступен с GitHub Actions.
2. Клонируй репозиторий в `/opt/recall` под этим пользователем. Если серверная
   копия уже запущена из другой папки, используй её путь. Так Compose продолжит
   использовать тот же проект и его том SQLite. Проверь от этого пользователя,
   что `git ls-remote origin refs/heads/main` работает без ввода пароля.
   Для приватного репозитория можно выдать VPS отдельный read-only GitHub Deploy Key.
3. Создай обычный серверный `.env` в этой папке. Укажи `TELEGRAM_BOT_TOKEN`,
   `TELEGRAM_ALLOWED_USER_IDS` и, если HTTPS уже настроен, `WEB_ORIGIN`.
   GitHub Actions эти значения не нужны. Если переходишь с локального
   экземпляра с тем же токеном, останови его перед первым запуском на VPS.

## Один раз в GitHub

Создай отдельную SSH-пару для входа из GitHub Actions на VPS. Публичную часть
добавь на VPS в `~/.ssh/authorized_keys` пользователя для деплоя. Закрытый ключ
для workflow должен быть без парольной фразы. В **Settings → Secrets and variables
→ Actions → Secrets** добавь:

| Secret | Значение |
| --- | --- |
| `RECALL_SSH_HOST` | IP или имя VPS без схемы и порта |
| `RECALL_SSH_USER` | Имя SSH-пользователя на VPS |
| `RECALL_SSH_PRIVATE_KEY` | Закрытый ключ GitHub Actions для доступа на VPS |
| `RECALL_SSH_KNOWN_HOSTS` | Проверенная строка `known_hosts` с публичным ключом самого VPS |

Для последнего секрета сверь отпечаток строки с отпечатком ключа VPS, полученным
через доверенную консоль сервера. Для Ed25519 команда на VPS —
`ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`. На своей машине можешь получить
строку через `ssh-keyscan -p 22 -t ed25519 <IP>` и проверить её отпечаток
`ssh-keygen -lf <файл-со-строкой>`. Для нестандартного порта в `ssh-keyscan`
используй фактический порт VPS.

В **Actions → Variables** можно задать `RECALL_DEPLOY_PATH` (по умолчанию
`/opt/recall`) и `RECALL_SSH_PORT` (по умолчанию `22`).

## Первый запуск

После настройки пуш в `main` запустит деплой. Если workflow попал в репозиторий
раньше, чем был готов VPS, после настройки запусти его вручную через **Actions →
Deploy Recall → Run workflow** на ветке `main`. Статус виден в Actions.
Команда `docker compose logs --tail=80 ideaflow` на VPS покажет лог приложения.

Healthcheck проверяет локальный HTTP-сервер. После первой выкладки отправь
тестовое сообщение боту. Для Mini App отдельно проверь HTTPS и кнопку бота с телефона.
